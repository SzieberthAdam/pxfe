**The pxfe changes**
- **Codes:** codes are now 40-bit numbers internally. The UI shows `U+0041`, `#3` for a glyph without a code point, `Default`, and `-001` after a variant. Code fields, Clone and the layer field accept `-V` to name a variant.
- **Writing:** the writer and reader use the new `GLYPH code advance x y …` line and the new line order.
- **Old formats:** these are refused with a message saying why:
  - a v2 pxfm file;
  - a version 2 or 3 draft (drafts are now version 4);
  - a pxfdb that still has v2 codes.
- **Settings file:** the per-database settings file moves to schema 4, and its correction codes are converted automatically when opened.
- **Packages:** the package code now reads the glyph and palette hashes from the new field positions. Without this fix, font packages couldn't be built.
- **Tests:** the testdata is regenerated. Its hashes match the spec's examples (`3b52125b…`, `4fba4190…`, `894ef821…`), and every old hash in the tests and scripts is replaced. I added unit tests for codes and variants.
